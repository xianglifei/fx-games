# 王城守卫 Castle Guard · 设计文档

## 定位

致敬经典 TD（Kingdom Rush / Kingdom Rush 前置的 Desktop Tower Defense 传统）的中世纪冷兵器塔防。约束：

- **单文件** `index.html`，无构建、无外部资源（字体/图片/音频全部程序化），`file://` 直开可玩
- 引擎与表现彻底分层，引擎可被 `node test.mjs` 原样提取执行——测试跑的就是线上那份逻辑
- 数值以模拟验证收敛：参考 AI 构筑必须通关且余耐久落在 5~10，裸奔必须败

### 引擎边界（可测性的关键）

- 标记段内**只允许纯逻辑**：状态是可 JSON 序列化的普通对象，随机只走 `rand(g)`（状态内种子），无 `Math.random`、无时间、无 DOM
- 演出与逻辑靠**事件流**解耦：`tick` 返回 `fire/land/hit/kill/leak/waveStart/waveClear/win/lose` 等事件，控制器消费为音效/粒子/飘字/横幅——经济守恒测试的"事件口径账本"用的就是同一条流
- 白盒测试与 Texas Holdem 同法：测试直接改引擎状态（摆塔、摆兵、设冷却），不绕 UI

## 关键机制

- **护甲** = 固定减伤（下限 1）；**破甲**按比例无视护甲（弩炮 50/75/100%）；**灼烧**为真实伤害（火油台）；三者构成克制链，全程无魔法
- **索敌**取射程内路径进度最前者（`e.dist` 最大）；弹道为追踪弹，目标死亡则扑空不结算——防止超杀重复发赏金
- **投石机**按目标当前速度预测 0.9s 后落点，落地对半径内衰减溅射（中心 100% → 边缘 40%）
- **火油台**无目标概念，冷却对范围内全体脉冲：真实伤害 + 减速（不叠加、只刷新持续）
- **提前出战**：备战剩余秒数 ×2 折赏金；首波备战不计时（`buildLeft = Infinity`，序列化用 `'__INF__'` 哨兵往返——`JSON.stringify(Infinity)` 会变 `null`，而 `isFinite(null)` 为真，直接序列化会让读档瞬间自动开战，这是实测踩过的坑）
- **无尽模式**为独立开局（400 金）：`mul = 0.75×1.07^n`，编成随波数解锁兵种，整十波出男爵

## 平衡方法

以 `test.mjs` 里的 `REF_PLAN`（30 条带波次门槛的建造/升级指令）作参考玩家，全 AI 跑 15 波：

- 通过判据：通关且余耐久 ∈ [5,16]；不建塔必须在前几波城破
- 首轮模拟暴露首波漏 4/20 过狠：验证「开局 +40 金」无效（计划门槛卡住花不出去），改**首波 8→6 民兵**后收敛为每波零星 1 漏、终局余耐久 7~9（5 个种子）
- 经济账本由测试锁定：期初金 + 击杀 + 波赏 + 提前奖励 − 建造 ≡ 期末金（事件口径分毫不差）

## 测试策略（298 项）

1. 地图/路径：长度、格数、端点、参数化连续性、可建格余量
2. 建塔校验：界外/路面/王城/装饰/占用/金币
3. 数值：护甲减伤与下限、破甲比例、真实伤害、溅射衰减、减速不叠加
4. 索敌弹道：最前优先、射程边界、死后转火、赏金只发一次、扑空箭矢
5. 波次：编成合法性、出怪数、自动开战、提前奖励、Boss 规律
6. 经济守恒（事件口径）
7. 确定性与序列化：同种子逐字节一致、存档续跑 ≡ 不中断、`Infinity` 往返
8. 全 AI 整局：参考构筑通关、裸奔必败、无尽 25 波 + 强度单调
9. 数据表合法性与性能冒烟

## 已知取舍

- 路径固定不放「堵路迷宫」：自由摆塔的乐趣保留，平衡面收敛为一张图
- 塔无逐塔索敌策略切换（先/强/近）：四塔定位已足够形成决策，避免 UI 膨胀
- 后台标签页 rAF 暂停即游戏暂停，属浏览器标准行为，不另做兜底时钟
